BUSINESS SCENARIO: The "JuanMart" E-Commerce Dilemma
-----------------------------------------------------

Company Profile:
JuanMart is a rapidly growing online retail platform based in Metro
Manila, Philippines. Over the past two years, they have expanded from
selling local artisanal goods to electronics, fashion, and home
groceries.

The Problem:
The CEO wants a clear picture of the company's sales performance to
plan next year's inventory. However, the data is scattered. Customer
registrations come from a web form, sales logs are extracted from an
older transactional database, and shipping logs are handled via text
files by a third-party logistics partner. Initial attempts to generate
reports produced conflicting numbers: the Finance team claims a 15%
revenue growth, while the Operations team reports a deficit due to
returns and cancelled orders. The data is plagued with duplicate
entries, missing fields, and chaotic formatting (e.g., region names
written as "NCR", "ncr", "Metro Manila", or "Manila").

Your Role:
You have been hired as the Lead Data Engineer. Your job in this module
is to apply the Data Analytics Life Cycle to understand the business
problem, profile the chaotic raw data, and write a programmatic Python
script to clean it before it enters the data warehouse.

LAB 1.2: PROGRAMMATIC DATA CLEANSING WITH PYTHON
---------------------------------------------------

Lab Description:
Now that you have a map of the data issues from Lab 1.1, you will
write a programmatic Python script in VS Code to fix them
automatically. This script will ensure the data is standardized,
clean, and reliable for the data warehouse loading step.

Step-by-Step Instructions:
  1. Create a new Python file in VS Code named 1.2_data_cleansing.py.
  2. Write functions to:
       - Drop the 15 duplicate rows.
       - Fill missing values in amount_paid with the median value of
         that region.
       - Standardize the region column using a mapping dictionary
         (NCR, Metro Manila, ncr -> National Capital Region).
       - Convert order_date strings to uniform YYYY-MM-DD timestamps.
       - Export the clean data to a new file: juanmart_clean_sales.csv.

LAB 1.4: SCENARIO GOAL
--------------------------

JuanMart's executive team needs an interactive BI dashboard to track
regional sales growth, monitor order volume trends, analyze customer
retention based on historical address migrations (from the SCD Type 2
pipeline), and identify top-performing product categories.

Recommended Tooling Option for Students:
  Streamlit / Plotly in Python (.py dashboard script).

Key Dashboard Deliverable Components:

  juanmart_analytics_dashboard File:

  - KPI Summary Cards: Total Net Revenue, Average Order Value (AOV),
    Total Orders, and Quarantined Data Error Rate (%).

  - Time-Series Revenue Trend Line: Monthly and quarterly revenue
    breakdowns using the dim_calendar dimension.

  - Geographic / Regional Heatmap: Sales density mapped by customer
    location (testing that the SCD Type 2 historical addresses
    dynamically map sales to where the customer lived at the time of
    purchase).

  - Product Category Performance: Bar/Donut chart breaking down sales
    volume vs. profit margins across product lines.
